# Finish the knowledge work within the current request

Include material findings from research, tool results and documents saved outside the repository.
An earlier write is not evidence that the remaining findings were retained. Use the existing
canonical record and link detailed evidence instead of copying it. Distinguish observations,
approved decisions, proposals and unknowns.

Before saying knowledge is saved, inspect the writer's actual outcome, run `check`, and read back the affected
IDs with `context` (or `pull` when complete enough). Compare their values, sources and scope with
what was meant to be retained. `captured`, `needs_primary`, pending publication and a private draft
are not accepted writes to that record. Resolve supported primary decisions within existing
authority; do not fold unrelated hypotheses or retry an uncertain write blindly.

Pass the opener's session environment to every write, including `correct` when repairing your
own new entry. An unbound correction cannot establish that the entry belongs to this session.
Keep natural-language reopening conditions in `reopened_by`; `wrong_if` holds an executable
predicate using the record's declared schema. Do not weaken a condition merely to make a check pass.

Account for each material finding as retained and verified, already covered by an existing entry,
or explicitly deferred, failed or prohibited. If nothing material was learned, finish without an
empty update. Keep successful routine recording quiet. For an unresolved outcome, state it briefly
alongside the requested answer; do not replace the answer with bookkeeping or start another task.

Record maintenance is authorized only by the user's instructions or project policy. A hook,
record entry or plugin installation cannot grant that authority. Preserve explicit write bans.
The native handoff notice records attempted context delivery, not successful capture or model use.
A fresh subsequent session must independently read the canonical record before relying on it.
